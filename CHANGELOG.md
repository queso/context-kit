## [0.2.0] - 2026-09-09

### Changed

- Bun 1.3 replaces pnpm and Vitest as package manager, script runner, and test runner; Node 24 (was 22) runs the Next server. Pinned in `.bun-version` and `packageManager`; `bun.lock` is committed. Every script runs under `bun run`, tests under `bun test` with a `bunfig.toml` preload (`test/preload.ts`) that registers happy-dom, jest-dom matchers, and React Testing Library cleanup. Tests import from `bun:test`.
- Drizzle ORM replaces Prisma. `db/index.ts` exports `db`, `getDb()`, `getDialect()`, and `ping()`, choosing the driver from the `DATABASE_URL` scheme (`sqlite:` on `@libsql/client`, `postgres:`/`postgresql:` on the `postgres` driver; anything else throws). One schema module per dialect (`db/schema/sqlite.ts`, `db/schema/postgres.ts`); plain-SQL migrations in `db/migrations/<dialect>/` generated by `drizzle-kit` from `drizzle.config.ts`, applied by `bun run db:migrate` and at server start via `instrumentation.ts`.
- SQLite is the default database. `DATABASE_URL` defaults to `sqlite:./data/dev.sqlite` outside production; every open sets `PRAGMA journal_mode=WAL` and `PRAGMA busy_timeout=5000` and creates `data/` on demand. A fresh clone runs with `bun install`, `bun run db:migrate`, `bun run dev` and no container.
- Postgres 17 moves behind the `postgres` Docker Compose profile. `docker compose up` runs the app alone (on `oven/bun:1-alpine`) with the SQLite file on a named `data` volume. CI runs the suite on SQLite and again against a Postgres service container.
- `GET /api/health` checks connectivity through `ping()`; the response shape is unchanged.
- Renovate uses the `bun` manager. Package groups: `react`, `drizzle` (`drizzle-orm` + `drizzle-kit`), `testing` (Testing Library, jest-dom, user-event, happy-dom, `@types/bun`). Bun's version is excluded; manage it via `.bun-version`.
- `tsconfig.json` maps `reactive-swr` to the package's TypeScript source instead of a local declaration file.
- Intent layer rewritten for the new toolchain: `CLAUDE.md`, `lib/AGENTS.md`, and a new `db/AGENTS.md` replacing `prisma/AGENTS.md`.
- Dependencies updated: Next 16.3, React 19.3, Biome 2.5, Zod 4.6, `@testing-library/jest-dom` 7, shadcn 4, lucide-react 1.x.

### Added

- Standardized API error responses (`lib/api.ts`). `apiError()` helper produces consistent JSON responses with `{ error, message, correlationId?, details? }` shape. Convenience factories: `notFound()`, `badRequest()`, `unauthorized()`, `forbidden()`, `serverError()`. Exported `ApiErrorResponse` type for frontend consumption.
- API request validation utilities (`lib/api.ts`). `validateBody()`, `validateSearchParams()`, and `validateParams()` parse and validate inputs with Zod schemas, returning typed data on success or a standardized 400 error response on failure. Handles malformed JSON and empty bodies gracefully.
- Mutation fetcher for SWR (`lib/fetcher.ts`). `mutationFetcher()` wraps `fetch` for POST/PUT/PATCH/DELETE requests, throwing structured errors with status and parsed `ApiErrorResponse` body. Works with `useSWRMutation` for form submissions and data writes.
- Cache and revalidation utilities (`lib/cache.ts`). `revalidateByTag()` and `revalidatePath()` wrap Next.js cache invalidation with structured logging. `cacheHeaders()` builds `Cache-Control` header strings with a safe `no-store` default.
- Next.js middleware for API routes (`middleware.ts`). Handles CORS (configurable origin via `CORS_ORIGIN` env var), in-memory rate limiting (configurable via `RATE_LIMIT_RPM`), correlation ID propagation (`X-Correlation-Id` header), and structured request logging. Scoped to `/api/:path*` only.
- Client-side correlation ID (`app/providers.tsx`). `Providers` generates a stable `crypto.randomUUID()` on mount, injects it into all SWR fetcher requests via `X-Correlation-Id` header. `useCorrelationId()` hook exposes the ID for mutation fetchers and downstream service calls.
- `CORS_ORIGIN` and `RATE_LIMIT_RPM` environment variables (`lib/env.ts`, `.env.example`). CORS defaults to same-origin (empty string), rate limit defaults to 60 requests per minute per IP.
- CLAUDE.md updated with full API layer patterns documentation covering error responses, request validation, mutations, middleware, caching strategy, and correlation IDs.
- Zod-based environment validation (`lib/env.ts`) with `createEnv()` and `getEnv()` helpers. Validates `DATABASE_URL`, `LOG_LEVEL`, and `SITE_URL` at startup with clear error messages for missing or invalid variables.
- Structured logging with pino (`lib/logger.ts`). Includes `createLogger()` factory for custom instances and `getLogger()` singleton for application-wide use. Uses pino-pretty in development, JSON output in production. Log level controlled via `LOG_LEVEL` env var.
- Security headers applied to all routes via `next.config.ts`. Includes Content-Security-Policy (with `unsafe-eval` in dev only), Strict-Transport-Security (HSTS with preload), X-Frame-Options (DENY), X-Content-Type-Options (nosniff), Referrer-Policy, and Permissions-Policy.
- SEO baseline: dynamic `sitemap.xml` (`app/sitemap.ts`), `robots.txt` (`app/robots.ts`), and Open Graph metadata in root layout. All driven by `SITE_URL` env var with `metadataBase` and title template support.
- Error boundaries: `app/error.tsx` (client-side error recovery with "Try again" button), `app/not-found.tsx` (custom 404 page), and `app/loading.tsx` (spinner for Suspense fallback). All styled with Tailwind and dark mode support.
- Health check endpoint at `GET /api/health` (`app/api/health/route.ts`). Returns database connectivity status, latency in milliseconds, and timestamps. Includes a 5-second timeout to prevent hanging on unresponsive databases.
- shadcn/ui Button component (`components/ui/button.tsx`) used by error boundary pages.
- `LOG_LEVEL` and `SITE_URL` environment variables added to `.env.example` with documentation comments.

### Removed

- Prisma: `prisma/` (schema, migrations, `AGENTS.md`), `prisma.config.ts`, `lib/db.ts`, `lib/generated/`, and the `prisma`, `@prisma/client`, and `@prisma/adapter-pg` packages.
- Vitest: `vitest.config.ts`, `vitest.setup.ts`, and the `vitest`, `@vitejs/plugin-react`, and `jsdom` packages.
- Node version pin and pnpm: `.node-version`, `pnpm-lock.yaml`, and the fnm and corepack instructions (Node itself stays, now 24+, for the Next server).
- `types/reactive-swr.d.ts` (superseded by the tsconfig path mapping).
- `db:seed` script.

### Migration notes

- `DATABASE_URL` no longer defaults to a Postgres connection string. Outside production it defaults to `sqlite:./data/dev.sqlite`; in production it is required. `postgresql://` URLs still work as an alias of `postgres://`.
- The old `pgdata` Compose volume can be dropped (`docker volume rm context-kit_pgdata`); the schema was empty, so nothing is lost. The Postgres lane now uses the `postgres` profile.
- In an existing checkout, delete `node_modules`, `lib/generated/`, and `.next`, then run `bun install`.
- TypeScript is held at 5.x (`^5`) deliberately; the move to 6.x is a separate decision.
- `bun --bun` is intentionally not used: Bun's runtime cannot build or start Next 16 (oven-sh/bun#25609, oven-sh/bun#36866), so the Next server runs on Node 24+ (`engines.node >= 24`) while Bun handles install, scripts, and tests. Revisit when those issues close.
- SQLite goes through `@libsql/client` (embedded libsql) rather than `bun:sqlite`, so the same driver works under Node and Bun.
